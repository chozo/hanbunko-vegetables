# ひと切り半分こ 〜野菜編〜

「ひと切り半分こ」シリーズの野菜編です（果物編：https://game.chozo.net/hanbunko-fruits/ ）。

立体の野菜をいろいろな角度から観察し、スワイプの一刀で **体積を 50:50** に切り分ける 3D ブラウザゲームです。
ナス → かぼちゃ → じゃがいも → キャベツ → ピーマン → 玉ねぎ → 白菜 → とうもろこし → 大根 → ブロッコリーの全 10 ステージ。成功すると次の野菜へ進み、失敗すると同じ野菜に再挑戦します。時間制限はありません。

- スマホ縦画面が主対象です。PC のマウスでも遊べます（PC では中央に縦長の画面として表示）。
- 3D 描画は Three.js、UI は HTML/CSS、効果音は Web Audio API で合成しています。
- ゲームの仕組み（操作・判定・切断と体積計算・演出）は果物編と共通で、野菜の形・模様・断面・効果音を野菜編として作り直しています。

## 起動・ビルド

```bash
npm install
npm run dev        # 開発サーバ（--host 付き。同じ LAN のスマホからも開ける）
npm run build      # 型チェック（tsc）+ dist/hanbunko-vegetables/ へビルド
npm run preview    # ビルド結果の確認
npm test           # 単体テスト（体積計算・切断・判定・空洞・初期姿勢）
npm run e2e -- http://localhost:5173/   # ブラウザでの動作確認（dev か preview を起動した状態で）
npm run ogp        # OGP 画像 → public/ogp.png（dev を起動した状態で。GAME_URL で URL を変えられる）
npm run promo      # 告知動画（30 秒・縦 1080×1920）→ ../video/（ビルドしてから撮影）
npm run deploy     # ビルドして Cloudflare Workers へデプロイ
```

### デバッグモード

URL の末尾に `?debug` を付けて開くと（例: http://localhost:5173/?debug ）デバッグモードになります。画面左上のステージ名の下に「DEBUG」の印が出ます。

- 失敗しても「次の野菜へ ▶」ボタンが出て、必ず次の野菜へ進めます（「もう一度」も押せます）。最後の野菜では「結果を見る」でクリア画面へ進みます。
- 判定と表示は通常どおりです。失敗した野菜はクリア扱いにならず、クリア画面の記録にも成功として残りません。
- 公開版でも `?debug` を付ければ使えます（遊び方の確認・見た目の確認用）。

## 操作

| 操作 | 内容 |
| --- | --- |
| 回転パッドを左右にドラッグ | 野菜を左右に回す |
| 回転パッドを上下にドラッグ | 野菜を上下に回す |
| 指を離す | 回転が止まり、その姿勢を保つ（慣性なし） |
| 「姿勢を戻す」ボタン | 初期姿勢に戻す |
| 失敗後の「もう一度」 | 切ったときの角度のまま再挑戦できる |
| 野菜の表示領域をスワイプ | 切る（指を離した瞬間に確定） |
| 右上のスピーカー | 音のオン・オフ（設定は保存） |
| PC のみ：矢印キー / R | 回転 / 姿勢リセット |

- 回転（下のパッド）と切断（上の表示領域）は操作する場所で区別するので、モード切り替えはありません。パッドで始めたドラッグは、野菜の上まで指が来ても回転のままです。
- 切断線は、指の軌跡が曲がっていても **始点と終点を結ぶ直線** です。ドラッグ中は光る刃の軌跡と、切断線の目安（点線）が出ます。
- 次の操作では切れません（理由を短く表示します）
  - タップやごく短い動き（表示領域の短辺の 14% か 40px の長い方より短い）
  - 野菜の上から始める・野菜の上で離す（野菜の外から始めて外で離す）
  - 野菜を横切らない（始点と終点を結ぶ線が野菜のシルエットに触れない）

## ゲーム仕様

- 誤差 = |片側の体積 / 全体の体積 × 100 − 50|。**誤差 1.0% 以内で成功**（49:51 は成功、48.9:51.1 は失敗）。
- 体積比は小数第 1 位まで表示し、判定も **表示と同じ丸めた値** で行います（`src/judge.ts`）。割合を 0.1 単位の整数に丸め、その整数で誤差としきい値を比べます。もう片側は 100 から引いて求めるので、表示の合計は必ず 100.0 になり、「表示では成功範囲なのに失敗」は起きません。
- 切る前に体積比や正解の位置は表示しません。
- 体積には皮・芯・わた・種を含む可食部の本体を数え、**ヘタ・葉の軸・ひげ根・軸（大根の葉の軸とひげ根、玉ねぎの乾いた首とひげ根、ナスのヘタ、ピーマンとかぼちゃの軸、キャベツと白菜の芯の切り口、とうもろこしのむいた皮・軸・ひげ）は除外** します。除外した部分も表示上は一緒に切れます。
- **空洞は体積に含めません。** ピーマンの中の空洞は、向きを反転した閉じた面として形に組み込んであり、その分だけ体積が減ります。断面にも穴としてそのまま現れます。かぼちゃのわたと種は詰まっているものとして体積に含めます。
- 表示の大きさは、どの向きに回しても画面に収まる球に合わせます。細長いとうもろこしと大根はそのままだと小さく見えるので、野菜ごとの表示倍率（`displayScale`）で、とうもろこしを 1.3 倍、大根を 1.35 倍にしています。縦長画面（360×640）で真横に向けても画面の幅に収まることを確認しました。
- 結果は切断平面の両側のグループとして、画面の左（横切りなら上）のかけらを先に表示します。
- 全ステージ成功でクリア画面（野菜ごとの挑戦回数と成功時の誤差）を出し、「最初から遊ぶ」で再プレイできます。
- 観察する意味を作るため、どの野菜も片側が張り出す・先が細る・反る・曲がるなど非対称な形にし、**初期姿勢のまま中心を縦・横に切ると 1% を超えてずれる** ように初期姿勢を選んでいます（`npm test` で確認。最小はブロッコリーの縦 1.17%）。

## 切断と体積計算の方式

表示・切断・体積判定は **同じ三角形メッシュ**（`src/geometry/mesh.ts` の `MeshData`）を使います。見た目だけ切る疑似判定ではありません。

1. **形状**：各野菜は手続き的に作った閉じたメッシュ（継ぎ目のない多様体）です。じゃがいも・玉ねぎ・ピーマン・かぼちゃ・キャベツ・ブロッコリーは「中心から見た方向ごとの半径」で決める星形の立体（`StarShape`）、ナス・白菜・とうもろこしは水平断面ごとに軸の位置と半径を決める回転体（`Revolve`、軸を曲げて反りを表す）です。ブロッコリーは頭（小房のこぶ）と茎（円柱）の半径をなめらかな最大値でつないで、ひとつの星形にしています。空洞（ピーマン）は、内側の閉じた面の向きを反転して本体に合わせます。ピーマンの胎座は、内側の面を上からくぼませて作ります（先が丸く上へ広がる双曲面）。壁・胎座・空洞が重ならないので体積は正確で、胎座が壁に溶け込む付近にはメッシュの輪を集めて精度を保っています。とうもろこしの粒は、回転体の半径に「16 列 × 先へ詰まる間隔」の格子で丸いふくらみを足して作ります（粒の境目でふくらみが 0 になるので面は途切れません）。二股大根は「胴」と「2 本の足」の 3 つの閉じた面でできています。胴の平らな底（股の円）を 2 本の足の上端（半円ずつ）がちょうど分け合うので重なりがなく、体積は 3 つの和になります。足の断面は上端の半円から下へ丸い形に変わるので、外側の表面は胴から足へ途切れずにつながります。
2. **切断平面**：スワイプの始点と終点を通る 2 本の視線を含む平面（= 切断線をカメラの奥行き方向へ伸ばした平面）をワールド座標で作り、その時点の野菜の姿勢の逆行列で野菜のローカル座標に移します。回転後の見た目と判定は常に一致します。
3. **切断**（`src/geometry/cut.ts`）：平面をまたぐ三角形を辺の交点で分割します。交点は辺ごとに共有するので、断面の境界はすき間なく閉じたループになります。ループを三角形分割（穴あきにも対応）して断面（キャップ）を作ります。ピーマンの空洞のように断面に穴がある場合も、外周と穴の向き（面積の符号）で区別して三角形分割します。
4. **体積**：発散定理で計算します。片側の体積は「切断で残った表面三角形と、平面上の 1 点を頂点とする四面体の符号付き体積の和」です。断面は平面上にあるので寄与は 0 になり、断面の三角形分割に頼らず倍精度で求まります。切断で生じる三角形は元の三角形をちょうど分割したものなので、両側の和は元の体積と一致します。
5. **断面の模様**：断面テクスチャは、断面の各点を野菜の形状定義に戻して「表面からの深さ」などを求め、皮・身・芯・種・層の色を決めて生成します（`flesh` 関数）。形と模様は同じ定義から来ているので、皮の厚みや芯の位置が形と食い違いません。

### 精度の確認（`npm test`）

| 確認 | 結果 |
| --- | --- |
| 球を高さ h で切った割合と解析解（球冠の公式） | 差 0.05% 未満 |
| 切断前後の体積の保存（各野菜 40 平面） | 0.001% 未満（ブラウザでの実測は 1e-13 程度） |
| 断面を含めた閉じたかけらの体積 = 断面に頼らない計算 | 1e-3% 未満（断面が正しく閉じている。穴のある断面も含む） |
| メッシュを 2 倍細かくしたときの体積比の差（各野菜 30 平面） | 最大 0.045%（ピーマン）、他は 0.03% 未満 |
| ピーマンを輪切りにすると断面に穴が出る | 断面のループが 2 つ以上 |
| 初期姿勢のまま中心を縦・横に切ったときの誤差 | すべて 1% 超 |
| 判定：表示値と判定の一致、境界値（48.95→49.0 成功 / 48.94→48.9 失敗） | 一致 |

メッシュは本物の野菜の近似ですが、ゲームが判定する対象は画面に表示しているメッシュそのものです。解像度による差は 0.02% 程度なので、1% 判定への影響はありません。

ブラウザでは `window.__game.verify()` が、直近の切断を **別の実装**（ワールド座標に変換した三角形を平面で切り取り直す）で検算し、判定との差と「断面の頂点が画面上でスワイプの直線からどれだけ離れているか（px）」を返します。

## 演出

1. スワイプ中：白い芯のある光の軌跡、火花、切断線の目安。軌跡の速さに応じた風切り音。
2. 切断確定：まっすぐな斬撃が画面を横切って光り、「シャキン」（金属的な倍音＋高域ノイズ）と野菜ごとの手応え（大根・じゃがいも・玉ねぎ・ピーマン・とうもろこしはシャキッ、ナスはやわらかく、キャベツ・白菜・ブロッコリーは葉が重なったザクザク、かぼちゃは固いザクン）。光った画面を 1 フレーム描いてから実際の切断を行うので、その処理時間とヒットストップで手応えを出します。
3. 切断直後：かけらが離れながら、断面がカメラへ向くように少し傾きます。傾ける軸は断面のいちばん奥の点に置き、傾けたあとのかけらが切断平面をまたがないよう実際の頂点で測って押し離すので、奥でつながって見えることはなく、2つのかけらの間には必ずすき間（`fx.separateGap`）が空きます。断面全体が野菜の色で強く光り、点光源が一瞬周りを照らし、断面から光の粒があふれます。光の色は野菜ごとに変えています（ナスは紫、かぼちゃはオレンジ、ピーマン・ブロッコリーは緑など）。
4. 結果：約 1.3 秒で発光が落ち着き、本来の果肉や種が見える状態で体積比を表示します。
5. 成功時のみ：光の輪と野菜に対応した色の粒子、「成功！」、チャイム。ボタンは少し間をおいてから押せます。失敗でも 1〜4 の演出は同じです。

| `timing.*` | ヒットストップ、斬撃、かけらが離れる時間、発光の保持・減衰、結果表示までの時間、ボタン有効化までの時間 |
| `fx.*` | かけらの間に空けるすき間・傾ける角度・切断後にカメラを引く倍率、断面の発光強度、パーティクル数と上限、ブルーム |
| `render.*` | 解像度の上限、重いときに解像度を下げる基準、断面テクスチャの大きさ（PC / スマホ）、画角、余白 |
| `audio.masterVolume` | 音量 |

野菜ごとの形・色・断面・初期姿勢・光の色・効果音の種類は `src/vegetables/*.ts`（共通の部品は `common.ts`）にあります。

## 素材の役割

ゲーム中は画像・音声ファイルを使っていません（読み込みに失敗する外部素材がない構成です）。画像は SNS 共有用の OGP 画像 1 枚だけです。

| 素材 | 作り方 | 役割 |
| --- | --- | --- |
| 野菜の形 | 手続き的なメッシュ | 表示・切断・体積判定の共通データ |
| 皮の模様 | 頂点色 + GLSL（ノイズ・ボロノイ） | 大根の横じわとひげ根の跡、じゃがいもの皮目、玉ねぎの薄皮の筋、かぼちゃのまだらとイボ、キャベツ・白菜の葉脈とちりめん、とうもろこしの粒（形そのもの）、ブロッコリーのつぼみの粒（いずれも凹凸付き） |
| 断面 | 形状定義から生成するテクスチャ | 皮・身・芯・種・層・穴。切るたびにその平面で生成 |
| 照明 | Three.js の RoomEnvironment + ライト | ツヤと立体感 |
| 光の演出 | シェーダー（加算合成）+ ブルーム | 刃の軌跡、斬撃、断面の発光、粒子、光の輪 |
| 効果音 | Web Audio API で合成 | 風切り音、切断音（野菜ごと）、成功・失敗、UI |
| OGP 画像 | `public/ogp.png`（1200×630）。`npm run ogp`（開発サーバー起動中）で作り直せる | SNS で共有したときのカード。切る前のブロッコリーと、かぼちゃをぴったり半分こに成功した結果画面を、タイトルと並べたもの。成功画面は判定をゆるめず、スワイプ位置を二分探索して本当に誤差 1% 以内になる切り方で撮る |
| アイコン | `public/favicon.svg`（包丁） | ブラウザのタブ |

- 音は最初のユーザー操作（「はじめる」など）で有効になります。AudioContext が使えない環境でも、音なしでそのまま遊べます。localStorage が使えない場合はミュート設定を保存しないだけです。
- WebGL が使えない環境では、その旨を表示します。

## スマホでの負荷対策

- devicePixelRatio は最大 2。平均フレーム時間が 24ms を超えると、解像度を段階的に下げます。
- ブルームは半分の解像度で処理し、粗いぼかし段の重みを下げて画面全体が霞まないようにしています。
- パーティクルは上限 1800 個の使い回しです。
- 断面テクスチャはタッチ端末では 256px にしています。生成時間は開発用の PC で 384px のとき 20〜60ms、256px ならその約半分です。
- 次のステージの形状は前もって生成しておきます。

## 制約

- 動作確認はヘッドレス Chrome（スマホ縦画面の 390×844 と 360×640、PC の 1280×800、タッチ操作の模擬を含む）で行いました（2026-10-15、`npm test` 39 件・`npm run e2e` 全項目成功。公開 URL に対する `npm run e2e` も成功）。スマホ実機での動作・描画・音は未確認です。
- 切断の手応え（ヒットストップ）の長さは、端末の処理速度によって多少変わります。
- 体積は表示しているメッシュに対して厳密ですが、実際の野菜の比重の違い（空気・水分など）は考慮しません。
